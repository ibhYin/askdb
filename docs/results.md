# 评测结果记录

每次正式评测都记一行。原始报告在 `runs/*.json`（不入库），这里只留结论。

复现命令：`make eval`（题目集：`data/sample/questions.jsonl`，24 题）

## 2026-11-01　第一次真实基线

模型：`deepseek-v4-1-flash-261017`（火山方舟 Ark，OpenAI 兼容接口）

| 轮次 | 题量 | EX | 平均步数 | 平均 token | P50 | P95 | 说明 |
|---|---|---|---|---|---|---|---|
| run 1 | 24 | 87.5% | 1.0 | 692 | 969ms | 2571ms | 3 题错 |
| run 2 | 24 | 95.8% | 1.0 | 709 | 1054ms | 2468ms | 修 q007 舍入口径后，2 题自动转对 |

> run 1 → run 2 的提升**不是模型变强**，而是修掉了一道 gold 口径歧义的题。
> 这正是先做评测器自检的意义：分数变化必须能归因到某个具体改动。

### 观察

1. **失败集中在"多返回列"**：问"哪些城市"返回城市 + 计数；问"占比"返回占比 + 订单数。
   SQL 语法和逻辑都对，错在没遵守"只回答问题所问"。
2. **同题两次结果不同**：q021 在 run 1 错、run 2 对，温度已是 0。
   服务端非确定性 → 单次分数是噪声，正式结论要跑 k 次取均值。
3. **样例集已饱和**：95.8% 意味着这套题量不出改进了，必须换 BIRD 100 题。

### 环境

- Python 3.13.4，SQLite 3（系统自带），openai SDK 3.42
- 单题平均 1.0 步即给出可执行 SQL，说明 24 题里没有触发"报错自纠"路径——
  这条路径目前只有单测覆盖，需要更难的题来验证

**量级与官方基线吻合（62.7 vs 61.0），说明评测链路可信**——这是我第一个能和公开数字对上的结果。

### 三个结论

1. **56 个错误全是"结果不对"**，没有一例 SQL 语法错或空结果。
   模型写的 SQL 都能跑，错在语义：选错 JOIN 路径、过滤口径不一致、没读懂 evidence。
   → 下一步该做的是 **schema 检索 + 少样本示例**，而不是加强报错自纠。
2. **平均 1.15 步**，几乎没触发重试。这直接否定了我原来的假设
   （"报错自纠"是主要提升点）——在 BIRD 上，第一次就写对的题占多数，
   写错的题再给一次机会也基本改不对。
3. **P95 67 秒、平均 3062 token**：长尾来自大库查询与长 schema。
   california_schools（列名带空格、多表嵌套）只有 28.6%，是最大的失分区。
   → 上下文裁剪与 schema 精简有明确的优化空间。

## 2026-11-02　A/B：表级 schema 检索（v1 提示词，同 150 题抽样）

| 配置 | EX | 平均步数 | 平均 token | P50 | P95 |
|---|---|---|---|---|---|
| 基线（全量 schema） | 62.7% | 1.15 | 3062 | 5.8s | 67.2s |
| + schema 检索 top_k=6 | **66.7%** | 1.21 | 3197 | 8.8s | 36.6s |

**+4.0pt（+6 题），token 只多 135，P95 反而从 67s 降到 37s。**

### 为什么 P95 降低

全量 schema 会把无关的大表塞进 prompt，模型容易在上面写无过滤的查询，
撞 10s 超时后重试（最多 6 轮）。裁剪掉无关表，长尾反而收敛。

### 表召回（离线，不算模型）

| top_k | 平均召回 | 完全命中 |
|---|---|---|
| 3 | 92.7% | 80.8% |
| 4 | 95.3% | 86.7% |
| 6 | **96.7%** | **91.7%** |
| 8 | 97.0% | 93.1% |

选 6：再往上边际收益很小，token 却线性涨。

### 校准记录

- 邻居扩展有两种策略：只补"自身也命中"的邻居 → 召回 93.3%、压缩更好；
  补全部外键邻居 → 召回 96.7%。**选了后者**：表没进 prompt 模型就写不出来，
  而 BIRD 的库不大，多几张表的 token 代价小于漏表的正确率代价。
- california_schools 从 28.6% 提升到 50%（14 题里错 7 题），是收益最大的库。

## 2026-11-02　A/B：提示词 v2（同 150 题抽样，无 schema 检索）

| 配置 | EX | 平均 token | P50 |
|---|---|---|---|
| v1 | 62.7% | 3062 | 5.8s |
| v2（先列定位/口径/聚合/输出契约） | 64.0% | 4385 | 10.7s |

**+1.3pt，代价是 token +43%。性价比很差。**

在同一批 60 题上再验证一次（带检索）：

| 配置 | EX | token |
|---|---|---|
| v1 + 检索 | 61.7% | 3202 |
| v2 + 检索 | 63.3% | 3755 |

方向一致（+1.6pt），但幅度仍小。

### 结论：v2 的"先想后写"收益有限

真正的收益来自 **schema 检索（+4.0pt）**，不是让模型多想几步。
v2 保留为可切换版本，但默认配置需要重新决定——
"多想"要花 43% 的 token，换来 1.3 个点，不值得作为默认。

### 附：并发验证

`--concurrency 4` 跑 60 题用 6 分钟（串行约 25 分钟），结果顺序不变。
并发下出现过 1 例"调用失败"，说明有速率限制，全量评测用 3 更稳。

## 2026-11-02 晚　全量 496 题消融

三组配置，并发 3，同一份 496 题评测集（坏题已隔离）。

| 配置 | EX | 答对 | 平均 token | P50 | P95 |
|---|---|---|---|---|---|
| A 基线（v1 + 全量 schema） | 57.7% | 286/496 | 3558 | 9.4s | 56.9s |
| B + schema 检索 | 57.7%（+0.0pt） | 286/496 | 3417 | **6.3s** | **38.5s** |
| C + schema 检索 + v2 提示词 | 61.9%（+4.2pt） | 307/496 | 4398 | 10.1s | 53.4s |
| D + 枚举取值样例（4 个/列） | **65.1%（+7.4pt）** | **323/496** | 4444 | **8.0s** | **37.8s** |

### 归因

每一步只加一个变量，所以可以干净地拆开：

| 这一步 | 准确率 | 其他 |
|---|---|---|
| B：schema 检索 | +0.0pt | token −4%、P50 −33%、P95 −32% |
| C：提示词 v2 | +4.2pt（286 → 307） | token +29% |
| D：枚举取值样例 | **+3.2pt（307 → 323）** | token +1%、P95 再降 16s |

取值样例是性价比最高的一步：**+3.2pt 只多花 1% token**，还顺带把 P95 从 53.4s 压到 37.8s
（模型看到 `'Directly funded'` 这种字面量，就不用反复试错）。

### 必须说清楚的偏差

A→D 的 7.4pt 是在**同一套 496 题**上调出来又测出来的：
提示词、检索参数、取值样例都是看过这批错题之后定的。
所以 65.1% 带有选择性偏差，和官方 61.0%（固定 prompt、未针对这套题调过）**不是严格可比**。

能说的准确表述是：
- 同一套题上，配置演进带来 +7.4pt（286 → 323 题）
- 与官方 61.0% 属于同一量级；本项目的 65.1% 含调参成分，**不宜宣称"超过官方"**

要排除这个偏差，需要在 BIRD 的 test split 或另一批未看过的题上复测——这是下一步。

### 与官方基线对照

官方 DeepSeek-V4.1-Flash 在 BIRD mini_dev SQLite 500 题上 **61.0%**。
本项目 496 题 **61.9%**，同一量级且略高。

**这是第一个能和公开数字对上的结果**——说明评测链路（gold 执行、结果比较、
坏题隔离）是可信的，比自建数据集上的任何高分都重要。

### 两次被自己的数据推翻

1. **150 题抽样上"检索 +4.0pt"是假的**：全量复核 286 对 286，一道题都没变。
   抽样本身更容易（62.7% vs 全量 57.7%），6 道题的波动放到全量就消失了。
2. **150 题抽样上"v2 只 +1.3pt、性价比差"也是假的**：全量是 +4.2pt。
   我一度把默认提示词改回 v1，是错的。

**结论：任何小于全量的对比都只能当方向，不能当结论。**
`docs/decisions.md` 第 9 条记了这条。

### v2 为什么在全量上更有效

按难度看：moderate 从 56% 提到 72%（+16pt），challenging 从 57% 到 61%。
v2 的四步（定位 / 口径 / 聚合 / 输出契约）主要修的是"选错表、口径不一致"，
这类题在 moderate 里占比更高。轻量样本里抽到的多为 challenging，
所以看不出差别——这也解释了为什么抽样会低估 v2 的效果。
